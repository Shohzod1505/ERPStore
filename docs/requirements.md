# Требования

## Цель

Offline-first MVP мини-ERP для магазина напитков: остатки по товарам и местам хранения, документы закупки/продажи/инвентаризации, касса и отчёт о прибыли.

## Функции MVP

- Товары: создание, остаток в штуках и блоках.
- Склады: создание складов и подскладов (один уровень вложенности), размещение товара.
- Закупка: создание черновика и отдельное проведение; при проведении остаток увеличивается.
- Продажа: создание черновика и отдельное проведение; при проведении остаток уменьшается.
- Инвентаризация: ввод фактического количества, корректировка остатка без перезаписи истории.
- Касса: приход, расход, выдача в долг, получение в долг.
- Отчёты: остатки, продажи, P&L.

## Решения по MVP

- У товара только название и `unitsPerBlock`; цены вводятся в каждой строке документа.
- Документ относится к одному месту хранения. Товар можно размещать и на складе, и на подскладе.
- Черновик можно только удалить; редактирования черновиков нет. Проведённый документ неизменяем, отмена проведённых не поддерживается.
- Инвентаризация предзаполняет все товары выбранного места. Недостача — расход, излишек — прочий доход.
- Касса одна. Ручной приход — прочий доход в P&L, ручной расход — операционный расход. Долги в прибыль не входят.
- Отчёты без фильтров по датам и охватывают всё время. Отчёт по продажам — список с итоговой суммой.
- Дата документа проставляется автоматически при создании.
- Деньги — `Long` в копейках, даты — `Long` epoch millis. `java.time` не используется.
- К сдаче: debug APK и JVM unit-тесты расчётов. README и скриншоты не требуются.

## Доменные правила

- Количество хранится только в штуках. Блоки — производное значение: `units / unitsPerBlock`.
- Документ имеет статус `DRAFT`, `POSTED` или `CANCELLED`; склад и касса меняются только при `POSTED`.
- Проведённый документ неизменяем; отменять можно только черновик.
- Документ относится к одному месту хранения.
- Продажа блокируется, если в выбранном месте недостаточно остатка.
- Себестоимость — средневзвешенная по товару. При продаже COGS фиксируется в строке документа.
- Инвентаризация создаёт корректирующее движение. Недостача уменьшает прибыль, излишек увеличивает прочие доходы.
- Закупка и продажа при проведении создают кассовую операцию.
- Долги не являются доходом или расходом: в P&L не входят, в денежный поток входят.
- P&L считается из проведённых документов и операций, итоговая прибыль не хранится.
- Деньги хранятся в копейках (`Long`), валюта — рубль.

## P&L

```text
Выручка         = сумма проведённых продаж
COGS            = Σ(количество × себестоимость на момент продажи)
Валовая прибыль = выручка − COGS
Прочие доходы   = ручные приходы + излишки инвентаризации
Расходы         = ручные расходы + недостачи
Чистая прибыль  = валовая прибыль + прочие доходы − расходы
Денежный поток  = все приходы − все расходы, включая займы
```

Закупка не попадает в расходы P&L повторно: её стоимость учитывается через COGS.

## Демо-данные

При первом запуске, если база пуста, создаются товары, склады и подсклады, несколько закупок, продаж, инвентаризация и кассовые операции. Данные создаются через реальные use cases, чтобы остатки, COGS и касса были согласованы.

## Вне MVP

Авторизация, сеть и синхронизация, несколько касс, переводы между складами, возвраты, кредитные закупки, частичные оплаты, редактирование черновиков и проведённых документов, отмена проведённых документов, фильтры по датам, экспорт, сканирование штрихкодов.
